# 기획서 대비 설계 결정·개선 사항

원 기획서(`DailyRoll — Claude Code 구현용 개선 기획서`, 기준일 2026-11-27)를 바탕으로 구현하면서 바꾸거나 보강한 점을 정리한다.

## 1. 플랫폼: 순수 Kotlin 앱 → Expo + Kotlin 로컬 모듈
- **이유**: 빌드를 EAS Build 로 하기로 결정(EAS 는 Expo/React Native 프로젝트만 빌드).
- **원칙 유지 방법**: 앱이 꺼져 있어도 알림 리스너·위젯이 동작해야 하므로 계산·파싱·저장은 전부 Kotlin(`modules/dailyroll-native`)에 둔다.
  JS 는 화면만 그리고 계산을 복제하지 않는다. 기획서의 "계산 규칙은 UI/DB 에 종속되지 않는 순수 Kotlin" 은 `domain/`·`money/` 패키지로 지키며,
  `tools/core-jvm` 독립 빌드가 android.* 의존이 섞이지 않았는지 컴파일로 검증한다.
- Compose 화면 → React Native 화면(expo-router). 하단 탭 3개(홈·리포트·설정) 유지.

## 2. Room → SQLiteOpenHelper, Glance → RemoteViews, DataStore → SharedPreferences
- Expo 로컬 모듈은 라이브러리로 빌드되며, KSP(Room)·Compose 컴파일러 플러그인(Glance) 버전을 Expo/RN 의 Kotlin 버전과 맞춰야 해
  EAS 클라우드 빌드가 깨지기 쉽다. 의존성을 늘리지 않는 쪽을 택했다.
- 대신 지킨 것: 버전별 마이그레이션 맵(destructive 금지·다운그레이드 차단), UNIQUE 제약 기반 idempotent 저장, 거래+원장 단일 트랜잭션, 인덱스.
- 위젯 반응형: Android 12+ `RemoteViews(Map<SizeF, RemoteViews>)`(런처가 실제 크기에 맞는 레이아웃 선택), 그 이전은 위젯 옵션 dp 로 선택.

## 3. 하루 예산 변경 이력(AllowanceSchedule) — 신규
- 기획서 공식 `dailyAllowance × dayOfMonth` 는 월 중간에 예산을 바꾸면 **이번 달 지난 날짜까지 소급**되어 잔액이 갑자기 바뀐다.
- `allowance_history(effective_from, amount)` 로 적용 시작일부터만 반영한다. 첫 설정은 과거 전체에 적용.

## 4. 연도 없는 날짜 추정 개선
- 기획서: 연말·연초 날짜는 `확인 필요`. 그대로 하면 12/31 23:58 결제가 1/1 00:02 에 도착하는 흔한 경우까지 모두 확인 대기가 된다.
- 구현: 수신 시각과 가장 가까운 연도를 고르고, **연도 경계를 넘으면서 3일 넘게 차이** 나거나, 하루 넘게 미래이거나, 45일 넘게 차이 나면 확인 필요.

## 5. 중복 판별 키
- 같은 알림의 재게시 판별 키 = `패키지 | 알림 key | Notification.when | 금액 | 유형`. 은행 앱이 같은 알림 id 를 재사용해도
  `when` 이 달라 다른 결제로 구분된다. 같은 출처의 다른 알림은 같은 금액·가맹점이어도 별개 결제로 보존한다.
- 다른 출처 병합 조건: 금액·유형·정규화 가맹점 일치 + 3분 이내 + 카드 끝자리(있으면) 일치. 하나라도 애매하면 `중복 의심`.

## 6. 파서 보강
- 카카오톡·삼성월렛 같은 간접 출처는 `카카오뱅크` 키워드 + 카드 문맥(체크카드/카드)이 모두 있어야 처리(일반 대화 오탐 방지). 신뢰도 상한 MEDIUM.
- InboxStyle 요약 줄에서만 찾은 결제는 개별 알림과 겹칠 수 있어 항상 확인 대기.
- 금액 후보 앞 10자에 `잔액·누적·한도·포인트·캐시백·적립·이용 가능·결제 예정·수수료·할인·청구`가 있으면 결제 금액 후보에서 제외.

## 7. 개인정보 보호 강화
- 릴리스 빌드에서 `INTERNET`·`ACCESS_NETWORK_STATE` 권한 제거(config plugin). 디버그 빌드는 Metro 연결 때문에 유지.
- `allowBackup=false` + `dataExtractionRules`(클라우드 백업·기기 이전 모두 제외).
- 알림 접근은 앱 내 동의(`consentAt`) 이후에만 처리. 동의 전 알림은 리스너가 받아도 버린다.

## 8. 위젯 자정 갱신
- 정확한 알람 권한 없이 `AlarmManager.set(RTC)` 부정확 알람으로 자정 직후 갱신을 예약(기기 깨어날 때 실행). 보조로 `updatePeriodMillis=30분`.
- 날짜·시간·타임존 변경 브로드캐스트, 원장 변경, 앱 복귀, 새로고침 버튼에서도 갱신. 정확한 00:00 실행은 보장하지 않는다.
